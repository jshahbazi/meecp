# A0R native recipe management harness

This additive checkpoint supplies a developer acceptance driver for the existing native Manage Recipes controls. It also repairs the lifecycle harness's private development admission to select exactly the registered current `ResolvedPythonComponent` reference. Public execution defaults remain closed.

The source base is `1364ceaa1fdc349f5c41974ab4627bead3bf4d14`. The backend saved-choice repair and its new immutable producer belong to a separate integration checkpoint. This source slice does not modify backend contracts, published components, recipe bundles, or templates.

## Native boundary

`McpmeMenuBar --recipes-native-acceptance /absolute/case.json` accepts only a private fixture below a private workspace named `mcpme-native-onboarding-*`. Its state directory must be the fixture's sibling `state` directory. A fresh UUID nonce, short expiry, and exact manager-connection file identity must match the private marker issued by the trusted acceptance harness. The driver consumes the nonce through an exclusive private claim file.

The fixture, marker, manager file, containing directories, and selected folder retain their observed identities. The driver checks current context before requests and mutations. Closed action and body allowlists restrict the driver to recipe add, inspect, refresh, enable, disable, deprecate, revoke, remove, and bounded ordinary generated-form inspection. It cannot start preparation, installation, a provider request, or model execution.

Folder-dialog choices and lifecycle confirmation choices are simulated fixture inputs. They enter the same completion and dispatch handlers as the ordinary file panel and alerts. The handlers, exact registry references, native forms, authenticated owner Unix socket, and parent callbacks are production paths. The receipt records the simulated inputs explicitly. The normal panel and confirmation alerts remain in the user flow.

The optional `forms` fixture checks an actual draft's exact recipe reference and blocker set. A `recipe:null` result must leave Choose selected and Review disabled. An explicit replacement uses the real native selection handler. The ordinary UI selftest separately checks that three null-recipe refreshes retain this state; its request callbacks are synthetic and do not constitute owner-socket acceptance.

## Lifecycle harness

The added `native_management` case scaffolds and checks two independently authored recipes through the installed CLI, then uses the native driver to add and inspect them. It exercises enable, disable, re-enable, deprecate, revoke, remove and refresh. It removes the original author bundles, restarts an ordinary execution-disabled host, and requires native inspect/refresh plus owner metadata to preserve exact removed recipe identities, epochs and evidence.

The existing nine lifecycle cases retain their real scheduler, verifier, stage-copy, native-owner and restart barriers. Their private factory now requires exactly one matching current bundled Python family; absent, old-version or duplicate matching references are rejected. Other registered families remain closed.

Before importing any selected host module, the harness validates clean source metadata, exact payload membership, and every artifact hash on the original host and relocated copy. It reuses the onboarding harness's strict inventory, which rejects symlinks, FIFOs, sockets and other special entries before hash reads.

## Focused verification

The private release build and focused tests cover closed fixture fields/actions, nonce mismatch, expiry, same-byte manager inode replacement, unsafe modes, hardlinks, symlinked folders, replay, existing output refusal, directory continuity, and pre-import payload mutation controls. Compiler and child output remain in memory; reports retain only fixed results, counts, types and hashes. Every launched test/compiler child is joined.

The final source packet records the exact test counts, native binary hash, input hashes and private receipt path. Two earlier local test attempts exposed test-control defects: a fixed stdout expectation mismatch and a macOS Unix socket path that exceeded its length bound. Both controls were corrected before the final packet. The independent review also found an incomplete special-file inventory in the initial harness; the strict existing verifier and actual FIFO/socket controls repair that defect.

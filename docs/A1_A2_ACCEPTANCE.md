# A1 and A2 signed checkpoint acceptance

A1 and A2 pass on the Developer ID signed local app built from `a8ec7b6875db9a466b7b1a00b1f5bd6a6b2c3eee`. This records the callable, existing MCP and exact CPU ONNX paths with the current common confinement. Public capability activation, the final combined source and release artifact, A3–A5 and the whole-phase adversarial review retain separate work.

The immutable app is `dist/mcpme-phase3-a1-signed-v2/mcpme.app`. Its complete 5,000-file inventory, 4,875 host payload entries plus `build.json`, native executable and Developer ID signature were preserved across the cases. Independent review rehashed all app files and every host entry, checked closed membership and read the actual entitlement scopes. The app is not notarized or published.

## Limits and guard checks

The ONNX workload passes the advertised 1 MiB encoded-image and 1,048,576-pixel limits, seven maximum-image cases, six controlled tensor cases, three blank-image cases and three boundary rejections. Each native case also checks four concurrent requests and three busy rejections. Maximum and relocated SDK probes run under the packaged confinement helper; their receipts retain their measured memory peaks and deadline observations. Synthetic results establish contract behavior; recognition quality has no acceptance claim.

The exact locked ONNX template environment passed all 30 detector controls, including incompatible tensor/layout/class metadata and provider checks. Five native harness controls passed in the host development environment. A preliminary mixed-suite run selected asynchronous host tests in the template environment, which lacks their async plugin; that failed trial is retained. The corrected environment-specific runs pass.

The ten recipe lifecycle races also pass on this same signed app: queued disable, verification/attachment revocation, active update, native cancellation, native owner crash and durable recovery, stale revision/source, capability denial and native recipe management. Exact restart bindings and ownership settlement agree. Only the lifecycle test harness changed at `bb5b5fe385912ec5df4688e62fd62064d1dd9f39` to preserve and verify the full signed bundle; production/backend bytes remain those of the original signed app.

The signed app's bundled interpreter passed 185 common contract/source/capture/job/authority checks and 18 independent creation-fence/final-admission/socket/confined-SDK controls, with 265 and 340 production modules respectively bound to the actual host. No model or provider calls occurred in these common controls.

The signed A1 probe initially exposed hardened-runtime rejection of upstream native wheels. The narrowly scoped [prepared-Python signing policy](PREPARED_PYTHON_SIGNING.md) fixes that loading boundary. Four actual import controls now pass. Only the generic prepared-app interpreter has the library-validation exception; the app, host SDK Python and helper have empty entitlements.

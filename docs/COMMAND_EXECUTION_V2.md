# Confined command ownership v2

Status: reviewed native ownership API on macOS 26 arm64, now exercised through the explicitly admitted [installed development-host checkpoint](COMMAND_INSTALLED_CHECKPOINT.md). Default admission, recipes and catalog remain disabled for this profile; the existing `ProcessOwner` and v1 receipt reader remain separate. **A3 remains open**, including aggregate process-count/memory enforcement and final native app artifact verification.

## API and admission

`backend/meecp/command_execution_v2.py` exposes `CommandExecutorV2`, immutable `CommandSpecV2`, `CommandResultV2` and sanitized `CommandExecutionError`. Compile `scripts/meecp-command-reap.c` as a separate helper and pass its exact SHA-256 when constructing the executor. The helper must be an owner-owned regular executable, without group/other write access or hard links. No fallback to the existing reaper is permitted.

The constructor requires a host `admit(spec) -> bool` callback. It must verify current preparation/runtime authority, an immutable verified package, the complete package digest, exact executable and supported effect declaration. Passing a digest string is a binding, not package validation. The host invokes admission before launch and again before returning output. Exceptions and revocation suppress output. The callback must be bounded and synchronous; it runs inside the serialized execution lane.

```python
executor = CommandExecutorV2(helper, pinned_helper_sha256, private_state,
                             admit=verify_current_admitted_package)
result = await executor.execute(command_spec, bounded_input_bytes)
await executor.close()
```

The spec fixes the package root, exact executable, working directory, immutable argument tuple, package digest, input/output byte ceilings, invocation deadline, TERM grace, settlement deadline and reservation units. Executable and working directory must resolve inside that package. Arguments never pass through a shell. The target environment is empty. Raw input and output remain transient. The bounded binary execution spec uses an anonymous temporary descriptor, unlinked before launch, and is closed in the target. There are no prompt, response, output or argument logs.

Installed integration additionally binds `authority_digest` into the specification and supplies a preallocated `instance_id` to `execute`; the native journal rejects reuse. The helper launches in its own session before native execution, protecting it from an ancestor process-group shutdown. The host still owns the helper's direct `Popen` handle and never reconstructs that authority from a PID.

Only the target's standard input/output/error descriptors survive exec. Standard error goes to `/dev/null`. The receipt, private state-directory capability, journal lock, host control channel and spec descriptor never reach selected code. A target may fork and exec the same pinned executable. Other executables and `posix_spawn` are denied. The profile admits package and named system reads; filesystem mutation, network connections, external signals and undeclared operations are denied. The admission review must check that these exact permissions suit the selected application. This implementation does not broaden a package's declared effects or enable general shell commands.

## Native ownership and receipt

The host durably creates the staging receipt and journal reservation before starting the native owner. It holds a private journal lock for the executor lifetime. A start-byte handshake transfers the writable receipt capability: the host closes its writable copy before permitting native execution. The native owner watches both its actual parent relationship and a control pipe. Host cancellation, control closure, owner death or its own invocation deadline initiates bounded cleanup.

Trusted child setup creates the isolated session, closes unrelated descriptors and installs the inherited Seatbelt profile before selected code executes. The profile denies `setpgid`, `setsid` and `posix_spawn` syscall entries. The third denial is necessary because both spawn group/session attributes bypass the first two entries. Fork and exec remain allowed. This policy is independently motivated by [the native feasibility packet](PREPARATION_CLI_DESCENDANT_BOUNDARY.md); it is a separately admitted topology.

The helper observes leader exit using `waitid` with `WNOWAIT`, retaining the exact child identity. It repeats signals only to that held group and queries `proc_listpgrppids` using a fixed two-entry buffer. Exactly one returned entry equal to the held leader is required. Other identifiers are discarded and never logged or signaled individually. Zero, errors and a foreign singleton permanently poison the current proof; a full buffer remains unsettled until a later singleton or the deadline. After reconfirming held exit, the helper waits for the exact leader and writes completion. A readiness re-read after exit closes the race where the session marker arrives between the first nonblocking read and `waitid`.

The v2 API now uses **publication format 3**: wire magic `MEECPC03`, journal version 3 and a fixed 301-byte receipt beginning with `MEECPCR3`. It binds a random instance, random nonce, helper SHA-256, policy/platform digest and full command-spec digest. The policy digest includes the fixed policy version, OS product version, kernel release/version and architecture. A `C` marker records proved group settlement and an encoded target exit status. A separate `N` marker records proved nonlaunch, either because host `Popen` never succeeded or because the native owner validated its receipt and never called a successful fork. Older journals are rejected without execution or automatic migration. Version-1 and old in-place version-2 receipts, including `C` and `N`, cannot satisfy the new contract.

The helper writes the complete payload to `<instance>.command-v3.pending`, changes it to owner-read-only mode `0400`, and calls `fsync` while that name is still unpublished. It verifies the exact staging inode, UID, link count, mode and bound content capability against the private directory FD. After closing its writable descriptor, it publishes with FD-relative `renameatx_np(..., RENAME_EXCL)` to `<instance>.command-v3.complete`. Existing destinations are never replaced. Recovery reads only the final name. A staged `C` or `N` is never proof, even if a previous native owner later fails or disappears. No fallible payload sync or rollback follows publication.

This ordering separates **payload durability** from **directory-entry persistence**. Every accepted visible final file contains the payload and private mode synced before publication. An unsynced rename can disappear across a filesystem or power crash; a missing final name always keeps the reservation pending. The implementation does not claim publication always survives such a crash. Normal host reconciliation durably updates the journal and syncs its directory, improving entry persistence. It never treats a later directory persistence failure as evidence that an already synced payload was invalid. The active host additionally retains observed native error state. These are filesystem `fsync` semantics; physical storage failure guarantees are outside the tested process-crash scope.

Membership proof failure, native-owner death, receipt failure or settlement timeout leaves the reservation pending. Cancellation joins the native helper within the declared cleanup budget plus a bounded startup margin; if that join cannot finish, the exact existing helper handle remains retained for later reaping, the receipt stays pending and new execution is blocked. No helper is killed to make an unsettled invocation appear joined.

Restart only validates exact private receipts. It never discovers processes, reads a PID from the journal, adopts a service or signals a recovered PID. A native owner that survives host SIGKILL can finish cleanup and write its receipt; a new host can then release the old reservation. If the native owner dies first, the reservation remains pending even when a synthetic fixture later exits on its own.

## Validation and remaining scope

Run `uv run --locked pytest -q tests/test_command_execution_v2.py`. The real native cases cover fork/exec inheritance, nonleader group/session escapes, both spawn attributes, child/grandchild cleanup, concurrent forks, descriptor and environment closure, denied file/network/signal effects, timeout/output limits, repeated cancellation, cancellation during actual forking, host SIGKILL before and during forking, native-owner death, receipt-only restart, old/foreign/truncated receipts, authority revocation and journal-before-launch ordering. Combined regressions kill the host after staged completion becomes visible but before delayed payload sync: successful sync later permits recovery, failed sync never releases the reservation or permits another invocation. Test-only compiled variants force query errors, zero, foreign singleton, full-buffer timeout, receipt-write/publication failure and missed initial readiness observation. Production code has no fault-injection switches.

Reservations are accounting units, not measured or enforced aggregate resource consumption. Per-process limits cannot establish a whole-tree memory or process-count bound. Production admission also needs independent complete-profile review, supported-OS validation, package/executable sealing, cancellation/settlement integration with the host's reservation ledger, receipt-format review and installed artifact verification. The current platform gate permits macOS 26 arm64; measured evidence is from macOS 26.7.1 build 25G241. No claim is made for other OS builds until verified.

# Fixed foreground process graph accounting

This optional trusted-host facility records existing `ProcessOwner` lifecycle evidence for a fixed graph of at most 16 roles. It does not introduce a native helper, change a wire/receipt format, launch selected source by itself, or enable any public profile. The host constructs `GraphMemberV1(role, executable, executable_sha256, declared_memory_bytes)` and `FixedProcessGraphV1(package_digest, authority_digest, members)`, then passes `graph_accounting=graph` to `ProcessOwner`. Every graph launch requires its explicit `graph_role`.

Graph owners additionally require a synchronous host-created `graph_admission_check` callback. It must return exactly `True` after checking current job/attempt authority and revision; false, integer aliases, awaitables and exceptions reject launch. The owner calls it after joined hashing and again inside the native creation task, checking its own closure state, fixed graph identity, startup deadline and reaper identity at those boundaries. No package or source chooses this callback. The common factory must bind its real metadata guard rather than a constant development-test answer.

The independent `ProcessOwner.launch(..., admit=trusted_check)` hook provides the same synchronous exact-True rule even without graph accounting. It runs inside the scheduled native task immediately before creation; graph-enabled launches also run it after hashing. A per-launch callback adds authority checks and cannot override the graph-bound callback. The default `None` preserves existing ordinary launch semantics. Managed preparation must pass its actual job/attempt/revision check, including when graph accounting is absent.

Each role has one attempt. The owner reserves its role/instance before a joined worker hashes its exact executable. A bounded metadata check immediately before native creation rejects changed bytes or identity. Existing `expected_reaper`, confinement, package/authority validation, nonlaunch callbacks and durable ownership protocols remain required. Executable hashing is an additional binding check; it supplies no new filesystem-write isolation or authority-expiry policy.

Native acknowledgments and terminal events update the graph through `OwnedProcess._observe`. Existing stop/close operations perform all cancellation and settlement. The recorder never discovers, adopts or signals a PID. Cancellation during hashing joins the worker and proves nonlaunch; cancellation during native creation joins existing launch/stop. Missing roles and unknown ownership remain incomplete. A graph cannot be attached to a second owner or reused to retry a role.

`graph.report()` returns frozen typed values with the graph contract digest, declared memory, per-member state and terminal foreground `wait4` RSS maximum. Where all members supply positive measurements, `conservative_member_rss_max_sum_bytes` is the sum of separate maxima. It is not a simultaneous live peak or task-footprint measurement. Depending on kernel accounting, a foreground maximum can include already-reaped child maxima; it still cannot certify lifetime descendant usage. Missing measurements and an overflowing total remain incomplete. `lifetime_descendant_coverage_complete` and `hard_aggregate_enforced` always remain false.

The graph is an in-memory observation, not a recovery certificate. Existing durable receipts and reservations remain authoritative. A new graph or a report cannot clear ownership left pending by a previous host. A proven nonlaunch role settles ownership but supplies no positive memory measurement; verification/attachment requirements are unchanged.

The existing A4 verifier accepts an optional trusted `graph_accounting` and forwards explicit engine/adapter roles. An injected owner must have that exact graph. Generic Python/ONNX factory integration remains owned by the common-probe lane. No model or GPU workload is needed for the graph's actual-native tests: two 2 MiB foreground fixtures exercise separate maxima, mutation before hash/spawn, repeated cancellation, helper loss, legacy measurement absence and bounded totals. The fixture's own alarm limits test orphan lifetime without turning elapsed time into settlement proof.

# Native captured ONNX installation acceptance

`scripts/verify_phase3_native_onnx.py` checks the visible intake component's actual
handlers, production owner socket, generated forms, managed preparation,
independent package probe, same-reviewed-revision attachment and CLI installation.
It relocates a clean hash-checked host, copies the compiled native binary, creates
private state and a minimal environment, and starts with empty private caches.
Its explicit trusted development factory enables the isolated runner for these
ONNX cases and requests only the ONNX task reference on hosts with separate
family admission. The frozen `2918a95` host uses its earlier global private
execution gate; it has no independently enforced per-family admission setting.
Ordinary production CLI preparation and resolution stay disabled.

Two cases use the real pinned model and its full AGPL license. One captures a new
model draft. The other supplements an ordinary folder containing only project
notes, preserving that folder's original source namespace. Neither case supplies
a preparation descriptor, app manifest, tool specification or dependency lock.
The native view adopts the settled draft and obtains the host-generated model
form and recipe. The reviewed package receipt must close over the exact
`onnxruntime-cpu-v1` engine and `yolo11-coco-detect-v1` task components.

Installation uses `install plan --import ID --revision N`, `install apply`, and
polling the actual operation. The real packaged MCP SDK checks the entire tool
contract and three synthetic image fixtures over both authenticated HTTP and
stdio. The original selected files and ordinary folder are deleted, the actual
host restarts, and both SDK transports invoke the installed app again. Exact
recipe digest and epoch survive restart; disabling the recipe and restarting
preserves that state while the installed package remains callable.

After the installed checks, the verifier copies the exact installed package,
joins the host, removes its known socket directory and deletes the entire
isolated original state, including captured artifacts. A separately owned SDK
probe invokes that relocated package, measures its own foreground process and
checks maximum byte/pixel inputs, concurrent busy rejection and boundary errors.
The report distinguishes these process peaks from aggregate live memory.

Shutdown joins retained `Popen` identities and checks installed ownership,
preparation reservations and ownership, capture jobs, read leases, job references
and GC journals. Unknown settlement or cleanup failure retains the isolated
directory and bounded diagnostic. Cleanup does not discover or signal PIDs.

## Run

Use a freshly compiled native binary and a complete clean reviewed host:

```sh
swift build --product MeecpMenuBar
uv run --locked python scripts/verify_phase3_native_onnx.py \
  --host /absolute/path/to/frozen-host \
  --native /absolute/path/to/.build/debug/MeecpMenuBar \
  --model /absolute/path/to/pinned/yolo11n.onnx \
  --output /absolute/path/to/new-bounded-report.json
```

The caller's model is only read and remains unchanged. A negative case mutates
one byte in its isolated copied selection while preserving its length and ONNX
format label. Actual native capture succeeds as data intake, but generated form
admission supplies no candidate and no preparation job. The exact packaged
family's separate static inspection identifies the unsupported model hash.
Synthetic fixtures and controlled tensors do not measure recognition accuracy.

Focused failure checks:

```sh
uv run --locked pytest -q --tb=no --disable-warnings \
  tests/test_native_onnx_acceptance_harness.py
.build/debug/MeecpMenuBar --artifact-capture-ui-self-test
```

The Python checks inject retained capture jobs, readers, job references and GC
journals, requiring the child to join and the exact evidence to remain. A cleanup
failure must preserve a bounded inspectable location.

with isolated `--ui-state-dir`. Computer-use verification opened **Add App**, used
both real file panels to choose copied model and license files, observed Capture
disabled before the license selection, reviewed 10.7 MB / five minutes / 64 MiB
and unverified publisher trust, and clicked the actual Capture button. The view
displayed waiting progress, adopted the settled model draft, selected the detected
YOLO recipe and displayed generated App name and Reserved memory questions.
Review displayed automatic preparation unavailable and kept Prepare Automatically
disabled. The owner joined the native process after normal Quit, and manager and
capture owner files were removed. This visible run verifies intake and form
handoff; the development installed harness supplies the execution evidence.

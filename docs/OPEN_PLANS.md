# Open implementation plans

Reviewed against the current source on **2026-10-08**, with the model-engine and consultant-delivery entries updated on **2026-10-11**. This inventory covers feature plans with unfinished implementation and explicitly deferred roadmap items. **Planned** means the feature is not implemented in the current source; **Partial** means a working foundation exists with the listed scope still missing; **Deferred** means the scope is documented without a delivery commitment. Later implementation and scoped acceptance records determine status where older checkpoint documents describe an earlier baseline.

| Plan | Status | Remaining implementation |
| --- | --- | --- |
| [Consultant delivery and commercial readiness](MEECP_COMMERCIAL_READINESS_PLAN.md) | Planned | Build the public reporting application, independent business oracle, metadata-only paired benchmark, and clean two-Mac/client protocol; measure the existing preparation, handoff, upgrade, and error-recovery workflows against Claude/MCPB. Then prioritize measured preparation/connection/support/distribution blockers and applicable Keychain/updater parity before a paid pilot. Existing host foundations are implemented within their scoped acceptance; this benchmark and commercial demand remain unverified. Fleet/hosted expansion and existing deferred package-update scope are not promoted by this plan. |
| [Automatic host updates](AUTO_UPDATE_PLAN.md) | Planned | Integrate the updater, signed release feed, update trust keys, shutdown/restart preflight, and replacement recovery. Manual DMG installation and restart already work. |
| [Custom app panels and Pi-generated workspaces](MEECP_CUSTOM_PANELS_PLAN.md) | Planned | Add package UI declarations, panel lifecycle/renderers, a scoped tool bridge, bundled web assets, previews, and independent UI verification. Remote/background panels and further panel capabilities are deferred within the plan. |
| [Whistle voice input](WHISTLE_VOICE_PLAN.md) | Planned | Add configurable activation starting with Fn, microphone capture, local transcription, focused-app dictation, and opt-in tool commands. Native permission handling, the inference helper, and release/privacy checks are also outstanding. |
| [Verified external-agent application identity](EXTERNAL_AGENT_AUTHORIZATION_PLAN.md) | Partial | Native approval, remembered account-scoped consent, leased sessions, and revocation work. A versioned resolver for verified application/launcher identity remains to be implemented. |
| [Start on first call](MEECP_DESIGN.md#ports-and-connections) | Planned | Wake a stopped eligible runtime on authenticated MCP initialization, coalesce concurrent starts, and preserve explicit Stop suppression. Current startup policies are Manual and Automatic when meecp opens. |
| [Automatic recovery after runtime crashes](MEECP_DESIGN.md#lifecycle-concurrency-and-resource-policy) | Partial | Host relaunch automatically settles recoverable abandoned foreground/group ownership before applying saved startup policies. Add bounded per-app retries/backoff and failure classification while preserving explicit Stop suppression; automatic crash restarts while the host stays open are not scheduled. |
| [Multiple model engines and broader GPU scheduling](MEECP_DESIGN.md#phase-4-multiple-model-engines) | Partial | The [experimental Rust Uzu package](UZU_EXPERIMENT.md) adds a second text-generation engine with pinned Qwen3.5-0.8B artifacts, a measured Metal comparison, and a [100-prompt blind quality screen](UZU_QUALITY_EVALUATION.md). The [isolated JevK5 probability-scoring follow-up](UZU_JEVK5_SCORING.md) has source/model conversion, a standalone exact-token CLI, and paired public scoring benchmarks complete. The [same-checkpoint BF16 control](UZU_JEVK5_BF16_CONTROL.md) also completed both rounds; probability and typed-scalar parity still failed, and calibration differences remain. The [Rust scoring hotspot experiment](UZU_RUST_SCORING_OPTIMIZATION.md) preserves exact Uzu outputs and shows a modest gain in a balanced 12-case control; full-population timing remains inconclusive and the optimizations stay opt-in. The [deeper Rust and Metal follow-up](UZU_RUST_DEEP_OPTIMIZATION.md) implements three additive candidates; its combined BF16 scorer passed complete-population exact probability, calibration, decision and vocabulary acceptance, and resumed balanced timing records a modest incremental gain on twelve selected cases. Full-population incremental timing improvement over original Uzu remains unestablished. The [full 243-case BF16 comparison with llama.cpp](UZU_OPTIMIZED_BF16_BENCHMARK.md) completed two monitored counterbalanced quartets and an independent Sol audit: optimized Uzu was 1.52–1.65x faster for fresh decisions with exact native probabilities/calibration/decisions preserved; cached repeats favor llama.cpp and the earlier cross-engine calibration differences remain. Background CPU activity limits precise timing claims. The [Sol implementation follow-up](UZU_SOL_OPTIMIZATION.md) adds bounded RoPE table reuse, compact GDN convolution buffers and KV-only final-layer preparation; the combined worker passed all 12 focused CPU/Metal tests and complete native bit-exact acceptance. Full timing against the current Uzu control and llama.cpp remains unverified: three attempts stopped on the background CPU guard, and a complete twelve-block renderer-pause attempt passed scoring/artifact audits but overlapped Mac sleep and is excluded from latency conclusions. All Uzu outputs and calibration stayed exactly unchanged; the additional Sol speed gain was inconsistent in the excluded run. No partial or sleep-affected timing is reused. The inherited malformed DeltaNet configuration gap remains outside fixed-checkpoint acceptance. The [consecutive scoring cache](UZU_SOL_CONSECUTIVE_CACHE.md) adds default-off single-entry whole-vocabulary logit reuse for identical consecutive tokens and context, with current candidate/temperature readout. Its isolated Sol worker passed full native exact probability, calibration, decision, vocabulary and lifecycle acceptance; hits skip native scoring. Precise cache timing is deferred. The [standalone Stark dependency path](STARK_DEPENDENCY.md) adds an exact source lock, explicit-commit build/update helper and isolated local checkout override; the pinned build and dirty local override passed 38 Rust tests each and full 243-case native bit-exact probability, calibration, decision, vocabulary and lifecycle acceptance on the fixed BF16 checkpoint, recorded in the [scoped acceptance receipt](../engines/STARK_VALIDATION.json). The [experimental Stark JevK5 package](STARK_JEVK5.md) adds an authenticated scoring bridge and the existing JevK5 HTTP/MCP adapter in its own model-service graph, retaining the llama.cpp package. Its [installed acceptance record](../engines/STARK_JEVK5_VALIDATION.json) covers all 243 native/API case pairs, real HTTP/stdio MCP clients, queues, default-off behavior and native-loss cleanup; short before/after timing remains a background-affected snapshot. Native KV-state reuse and general Stark generation/Pi integration remain outstanding. Extend admission beyond one resident GPU package and establish broader contention, queue saturation, pressure, and lifecycle behavior; stronger model/profile quality evidence and full Phase 4 acceptance also remain. |

| [Keychain-backed secrets](MEECP_DESIGN.md#transaction-and-recovery-rules) | Planned | Add a Keychain storage backend. Current immutable secret references use owner-only private files. |
| [Automatic secret rotation](MEECP_DESIGN.md#transaction-and-recovery-rules) | Planned | Add managed rotation and its runtime/configuration transition. Current rotation creates a new reference and requires a reviewed configuration upgrade. |
| [Remove app and delete data](MEECP_DESIGN.md#transaction-and-recovery-rules) | Planned | Add explicit deletion of retained app data/configuration. Existing removal stops the app and revokes its connection while preserving recovery material. |
| [Installed-package artifact retention cleanup](MEECP_DESIGN.md#transaction-and-recovery-rules) | Planned | Add retention policy and cleanup for old installed packages, shared artifacts, and recovery material without deleting live or required recovery state. | [Post-exposure repair and restore plans](MEECP_DESIGN.md#transaction-and-recovery-rules) | Planned | Add separately reviewed repair/data-restore plans with compatibility and write-loss review. Existing cancellation and recovery preserve the selected generation after exposure; they do not restore an older data snapshot. |
| [Installed-package OS isolation](MEECP_DESIGN.md#monitoring-and-local-trust) | Deferred | Add enforceable filesystem/network isolation for installed packages. Current package processes run with the user's permissions; restricted preparation probes have their own narrower confinement. |
| [Executable preparation-worker extensions](PHASE3_STATUS.md#continuing-boundaries) | Deferred | Admit additional executable recipe workers with explicit capabilities, confinement, cancellation, and descendant ownership. Declarative recipe authoring and its supported lifecycle are implemented. |
| [Further recipe-backed provider and model families](PHASE3_STATUS.md#continuing-boundaries) | Partial | Extend the accepted fixed recipe/provider scope, including further runtime/model families, GPU/Metal preparation, resident vision, and GUI automation. Pi already supports multiple providers and custom builds; each additional recipe admission retains its own acceptance gate. |
| [Reference-document service onboarding](PROJECT_ONBOARDING.md#delivery-order) | Planned | Add a supported document-service template with search/read tools, source references, parsing limits, and update behavior. Reference-role drafts remain blocked; Markdown/text setup briefs already work. Broader PDF extraction and OCR are deferred within this plan. |
| [Automatic installed-package updates](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Add package update discovery and scheduling through the existing reviewed upgrade path. This is separate from automatic host updates. |
| [Shared inference engines across apps](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Share an engine across slot boundaries with explicit ownership, admission, and lifecycle rules. Clients of one model app already share that app's engine. |
| [Package marketplace and publisher trust policy](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Add a public catalog, publisher onboarding/verification, and package distribution trust policy. Prepared local packages and pinned download links already work. |
| [Remote/cloud workers](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Add remote worker transport, authority, supervision, and recovery. Current execution is local. |
| [Container/VM execution](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Add isolated container or virtual-machine execution profiles and their lifecycle/resource contracts. |
| [Intel Mac support](MEECP_DESIGN.md#deferred-scope-and-choices) | Deferred | Add x86_64 runtime/package support and compatible distribution builds. Current bundles target Apple silicon. |

# Public native command acceptance

`scripts/verify_phase3_public_native_command.py` verifies an already active,
signed command release through the shipped CLI and production native directory
handler. It accepts the matching `.app` host/native pair, an explicitly compiled
synthetic `host_command_target.c` fixture and a new private JSON report path.
Run it with the candidate host's Python 3.12 and bytecode writes disabled.

Every ordinary startup and restart calls the common CLI harness with
`enabled=False`. The driver does not construct host admissions, replace the
Supervisor or supply preparation/resolution factories. Its fixed release-policy
check requires the reviewed command component, platform digests, admitted family
and exact singleton component closure. A missing or closed record fails before
host startup. Inventory presence cannot enable the driver or the app.

The initial review checks the actual CLI capabilities, enabled recipe closure,
generated command form and production `plan-form` response. Review must produce
an executable plan and create no preparation or resolution jobs. The full case
then runs native directory selection, generated answers, measured preparation,
matching attachment, installation, actual HTTP and stdio SDK calls, source-free
restart, original state removal and installation from a relocated sealed package.
Source selection and form answers are bounded acceptance fixtures supplied to
the same production native handler; physical dialog clicks remain unverified.

The common relocation helper preserves the complete signed `.app`. The public
driver requires the reviewed Developer ID certificate and Team, hardened runtime,
timestamp and empty app/helper entitlements. It captures complete original app
file identities, modes and hashes plus the supplied fixture before running, and
checks those original inputs again afterward. It does not sign, acquire credentials,
invoke model inference or call providers.

Optional `--upgrade-app` supplies a genuinely separate signed build whose two
command helpers have exactly the same approved bytes. The driver reopens the
first build's final installed state with the second shipped CLI and calls the
existing sealed package over HTTP and stdio. It performs no reinstall and checks
the slot generation, package identity, complete tool schema and original sealed
package files. Both original apps remain unchanged. Omitting this input explicitly
leaves cross-build upgrade acceptance unverified.

The inherited topology/crash controls remain trusted private embeddings and are
reported under `additional_private_fault_controls`. They do not establish public
fault-path admission. Deliberate ancestor-group loss retains unjoined legacy
gateway authority and a reconciliation-required workspace. The report therefore
distinguishes joined driver children and settled ordinary public installation
from overall ownership settlement. It does not claim hard aggregate memory
enforcement or complete lifetime measurement.

Focused tests use synthetic metadata and transport replies to check ordinary CLI
routing, active-policy requirements, form/recipe/review gates, no-job review,
complete input identity preservation and separation of the private fault scope.
They do not establish acceptance of the final signed release. That run requires
the final integrated backend, immutable new producer and active signed policy.
Earlier private proof scripts and receipts remain unchanged.

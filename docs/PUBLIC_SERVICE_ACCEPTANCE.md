# Public local-service acceptance

`scripts/verify_phase3_public_service.py` consumes an explicitly supplied signed
app's matching `--host` and `--native`, plus an exclusive `--output` report path.
It requires the shipped fixed release policy to admit the immutable
`service-text-generate-v1@1.0.0` task and the exact three-component closure from
the reviewed service checkpoint. The ordinary CLI starts every host. There is
no factory injection, environment execution switch, recipe enablement, model
selection, or credential discovery.

The test peer is an authenticated synthetic OpenAI-compatible HTTP endpoint on
an ephemeral `127.0.0.1` port. It validates a bounded request and returns a fixed
protocol fixture. It does not implement a language model. Its credential is
created deliberately in the isolated host and is never logged or included in
the output report.

## Native boundary

The shipped `--service-native-acceptance` entry selects controls in the actual
`ServiceConnectionView`, invokes its Save action, and retains the production
parent callback and owner-UDS transport. The existing generated form actions
review and start preparation. Before Prepare, the native entry checks that
both preparation and resolution job lists are empty. It does not substitute a
compiled helper or a synthetic form response for the shipped application.

The fixture is developer-only authority to operate these owner actions. It is
bounded to a private workspace/state, a current manager-file identity, an
expiring nonce, an exclusive one-shot claim, and an exact service-only route
allowlist checked before requests and callback consumption. It permits no
provider, agent, resolution-start, installation, or arbitrary network route.
Secret values cannot appear in the fixture; it selects an opaque saved UUID.
Malformed, stale, replayed, linked, permissive, and wrong-namespace contexts
must fail without consuming a fresh claim. The shared directory and agent
context behavior remains covered by its existing compiled tests.

Programmatic AppKit control selection is recorded honestly. This entry does
not prove physical mouse clicks, dialog appearance, accessibility usability,
or a human visual review.

## Required actual flow

The driver checks truthful service capabilities and exact policy/component
identity before executing a service case. Native intake creates a virtual
service source with no locator or files. Confined preparation must produce one
authenticated compatibility call, a schema-3 receipt with schema-2 service
inputs, two checked tool definitions, an exact matching attachment, settled
ownership and released reservations. Package metadata must exclude the host
secret UUID, credential value and private state path.

Ordinary reviewed installation exposes `generate` and `check_connection` over
both official SDK transports. The driver then removes the original recipe
registration, stops and joins that host, and installs an exact copy of the
accepted sealed package into a fresh isolated host with a separately reviewed
logical `api_key` setting. That new host deliberately selects a fresh UUID.
This installation does not rewrite the original preparation receipt or imply
that the original probe verified the replacement UUID.

Once both hosts have joined, the original isolated state—including original
source/import records and host-copied recipe bytes—and exported package are
removed. The retained installed package and settings must work after restart
over HTTP and stdio. This avoids editing live audit rows or manufacturing a
dummy original directory. The signed author recipe in the immutable app is
preserved throughout.

Revoking an unrelated synthetic secret must preserve both transports. Revoking
the selected installed secret must stop the slot and empty its owned-process
ledger while leaving the external test peer alive. Local ownership settlement
does not establish cancellation or settlement of work inside an external
service.

The original and relocated app inventories, strict pinned Developer ID
signatures, signed runtime assets, command helpers, native executable and
recipe bytes remain unchanged. Every owned child and fixture connection is
joined. The report retains bounded hashes, counts, fixed stages/codes and
booleans; native failure diagnostics are projected before temporary cleanup.

## Checkpoint limits

Source controls validate policy denial, diagnostic filtering, ordinary launcher
selection, the synthetic HTTP peer and compiled native fixture guards. An actual
public installed run requires a newly built coherent signed app that contains
this native entry and the admitted service closure. These source controls alone
do not establish that run. Gateway workloads must run in an exclusive window
because existing host port allocation uses a shared preferred range.

Actual language-model behavior, remote TLS/provider compatibility, live provider
acceptance, physical UI operation and upstream work settlement remain separate
claims. This driver neither enables nor claims them.

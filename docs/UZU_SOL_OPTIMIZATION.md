# Sol Uzu optimization experiment

Three Sol agents implemented additive candidates after the [Rust review](UZU_SOL_RUST_REVIEW.md) and [Metal review](UZU_SOL_METAL_REVIEW.md). All features are disabled by default and extend the previously accepted deeper scorer. The original and accepted workers, model exports, reference records and reports remain immutable.

| Candidate | Implemented scope | Acceptance |
| --- | --- | --- |
| [RoPE tables](UZU_SOL_ROPE_IMPLEMENTATION.md) | Bounded model-owned CPU table reuse, keyed by complete immutable configuration and absolute position; original formulas and GPU upload retained. | Combined candidate passed 12 focused CPU/Metal tests and complete exact native acceptance; component-specific speed is unmeasured. |
| [GDN buffers](UZU_SOL_GDN_IMPLEMENTATION.md) | Compact convolved QKV with original projection retained for controls/gates, explicit read strides, original arithmetic and dispatch. | Combined candidate passed 12 focused CPU/Metal tests and complete exact native acceptance; component-specific speed is unmeasured. |
| [KV preparation](UZU_SOL_ATTENTION_IMPLEMENTATION.md) | Dedicated KV-only preparation on inherited eligible final-layer cache-only batches; dead query normalization, RoPE and stores omitted. | Combined candidate passed 12 focused CPU/Metal tests and complete exact native acceptance; component-specific speed is unmeasured. |

The [acceptance protocol](../experiments/uzu-rust/jev-scoring/SOL_VALIDATION_PROTOCOL.md) requires binary64 equality against the sealed original native Uzu reference on all 243 cases, repeat inputs, 48 context boundaries and 534 complete-vocabulary digests. The [timing protocol](../experiments/uzu-rust/jev-scoring/SOL_BF16_PROTOCOL.md) compares the accepted combined candidate with both unchanged llama.cpp and the prior accepted Uzu worker, using the same BF16 checkpoint. Its target scope is all 243 cases, four loads per engine, 5832 measured responses and 36 checked warmups. One complete run passed scoring and artifact audits but overlapped system sleep; its timing is excluded.

Native identical-state reuse, production HTTP/MCP scoring integration, installed JevK5 package acceptance and broader model/generation acceptance remain outside this experiment. Final-visible-row tile pruning is deferred because complete preservation of live tiles and reduction geometry is unproved. The inherited malformed DeltaNet configuration gap remains outside this fixed-checkpoint optimization scope.

The [native test record](../experiments/uzu-rust/jev-scoring/SOL_NATIVE_TESTS.json) passed all 12 focused engine tests. Production worker/probe builds used ordinary Rust 1.98.1; the custom upstream test framework used test-only `RUSTC_BOOTSTRAP=uzu_engine`. Worker tests passed separately. The [native acceptance result](../experiments/uzu-rust/jev-scoring/SOL_VALIDATION_RESULTS.json) and [independent audit](../experiments/uzu-rust/jev-scoring/SOL_VALIDATION_AUDIT.json) preserve every candidate logit, log probability, probability and typed decision bit, plus every vocabulary digest on all case/boundary requests. This proves the combined candidate for the fixed JevK5 scoring scope. It does not isolate any individual candidate's latency contribution. Full timing against the current accepted Uzu control and llama.cpp is pending a complete monitored retry.

The first full timing attempt completed four loads and stopped during the fifth when one background process reached 265.1% CPU. The predeclared 200% guard stopped the owned benchmark, all workers were reaped, and the attempt is excluded from final timing. Aggregate-only samples cannot attribute that historical spike. The [versioned retry protocol](../experiments/uzu-rust/jev-scoring/SOL_BF16_RETRY_PROTOCOL.md) preserves all original sources and criteria, binds both protocols, records peak process identity privately, and hardens final sampling/receipt failures. The three coordinated chats were released between attempts.

The first retry also stopped after four completed loads: the private record identified the Codex renderer at 262.9% CPU. It is excluded entirely, and all owned workers were reaped before releasing the coordinated chats. A second retry used the same frozen retry sources, protocol and CPU guard, with progress redirected to a private content-free file and minimal UI output. It stopped after three completed loads when the Codex renderer reached 291.2% CPU. Reduced UI output did not resolve the interference. The [scalar attempt record](../experiments/uzu-rust/jev-scoring/SOL_TIMING_STATUS.json) preserves all three exclusions and receipt hashes. No partial blocks contribute to a speed estimate. All model workers were reaped, and coordinated work was released after every interruption.

Final Sol review found no blocker in the admitted scoring path. It found that the immutable retry parser also accepts wider llama.cpp readouts, although this protocol requires top-40. The current attempt configurations have both readout fields set to 40. The additive [readout verifier](../scripts/audit_jev_sol_readout.py) rejects other widths and verifies the completed report/audit/seal chain; all 40 supplement tests passed. It supplements the full independent audit without modifying bound historical sources.

The [bounded renderer-pause proposal](UZU_SOL_RENDERER_LAUNCHER_PROPOSAL.md) supplies a separate opt-in launcher around the unchanged retry monitor. It reserves restoration time, checks the exact native process identity and uses a detached watchdog to attempt resumption on completion, launcher loss or deadline. Independent Sol review, 38 mocked tests and a live identity dry run preceded explicit human authorization. The authorized run completed all twelve blocks; native observations independently verified the matching renderer stopped and running again afterward. Both launcher and monitor exited zero, all model workers were reaped, and all three coordinated holds were released.

The [completed-run result](../experiments/uzu-rust/jev-scoring/SOL_BF16_RESULTS.json), [independent audit](../experiments/uzu-rust/jev-scoring/SOL_BF16_AUDIT.json) and [top-40 supplement](../experiments/uzu-rust/jev-scoring/SOL_BF16_READOUT_AUDIT.json) passed the frozen scoring/artifact checks for 5832 measured responses and 36 warmups. Uzu probabilities, calibrated decisions and quality remained exactly equal to the reference. Sampled host screening found no competing model/compiler work or CPU-guard violations; maximum background process CPU was 191.8%. A separate power-log check established clamshell sleep within the whole run window. Python's `monotonic` and `perf_counter` use `mach_absolute_time`, which excludes Mac sleep. The legacy launcher's wait limit therefore did not bound wall time across sleep. Per-request sleep overlap cannot be established or ruled out. The [attempt disposition](../experiments/uzu-rust/jev-scoring/SOL_BF16_RENDERER_WINDOW_STATUS.json) excludes the entire timing result; successful scalar reproduction does not establish uninterrupted latency.

The stored fresh-decision ratios were 3.4465x and 1.8171x for llama.cpp over the Sol candidate. The prior Uzu control over the candidate was 1.0431x and 0.9881x: the additional gain was inconsistent across cycles. Cached llama.cpp repeats had 3.26x and 7.30x lower mean latency. These are descriptive values from the excluded attempt, with no accepted new speed claim. The three earlier interrupted attempts remain excluded independently. The [versioned awake launcher](UZU_SOL_AWAKE_LAUNCHER.md) now uses a sleep-inclusive deadline, an owned idle-sleep assertion and a predeclared whole-window sleep check. All 36 new mocked tests passed; the wrapper has not been used for a model run. The user deferred further precise timing and requested investigation of consecutive-request reuse.

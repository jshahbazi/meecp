# Sol review of optimized Uzu Rust scoring

Reviewed on 2026-10-11. This is a source review of the pinned Uzu 0.6.1 revision `8d01581474760bd1fc7f4a547ff1d02f7dada437`, the current `all` source snapshot, the original worker/scoring sources, and the next-token, topology, deferred-initialization, submission and last-layer patches. The existing [deeper experiment report](UZU_RUST_DEEP_OPTIMIZATION.md) supplies historical acceptance and timing context. This review ran no builds, tests, inference, model hashing or profiling and changed no existing bound artifacts. It adds this report only.

No demonstrated correctness defect was found in the current serialized fresh-state scorer. Source inspection supports its resource lifetimes, batch acceptance and narrow pruning conditions. That conclusion does not establish failure-injection behavior, broader generation/tree acceptance or a further speed gain. The most concrete next candidates remove repeated immutable setup work; the larger GPU opportunity is output-tile pruning with the original execution geometry retained.

## Correctness and lifetime findings validated from source

1. **The new submission guard covers normal error exits after submission.** The transformer state is created before `final_logits`, and both precede `ScoringSubmissions`; reverse local destruction therefore drains pending GPU work before dropping either resource. A later allocation or decoder error triggers the guard. `drain_submissions` retains the first returned error while waiting on every pending item. Its tests cover returned errors and empty/success queues (`scoring.rs:208–237`), not actual Metal device failure or panic inside the wait operation. Metal waiting uses a blocking completion channel (`command_buffer.rs:295–303`). This review does not strengthen that backend completion contract.

2. **Independent pools are necessary while encoding overlaps submitted work.** Dropping a scratch handle immediately returns its page to its allocation pool (`allocator/pool.rs:61–64`). Each scoring batch gets a distinct pool (`scoring.rs:136–144`), and Metal carries the pool into its pending handle and feedback closure (`command_buffer.rs:260–283`). This prevents host encoding of the next batch from acquiring pages still used by earlier batches. Replacing those pools with one shared pool before completion would introduce unsafe storage reuse.

3. **Host state advancement can precede GPU execution because later encoded work remains ordered.** Full attention acceptance advances the host prefix length and emits no copies for identity accepts (`attention/state.rs:107–130, 251–269`). Flat GDN forward encoding already writes recurrent state; its acceptance clears the suffix marker after checking the final accepted index (`delta_net.rs:73–86`). Later batches encode offsets from those updated host values. They use the same queue, with device-visible entry/exit barriers (`command_buffer.rs:76–80, 230–239`). The scorer prepares all attention storage before its first submission (`scoring.rs:126–129`), avoiding sparse mapping/resizing between in-flight batches.

4. **Removing token-history bookkeeping preserves positions in this scorer.** Topology is local to each chunk. Absolute RoPE positions come from `TransformerState.context_length + topology.height` (`transformer.rs:275–282`), and every non-final part calls `encode_accept`, which increments that context (`transformer.rs:82–101`). Thus removal of `state.tokens.extend` does not reset positions. The topology test compares legacy nodes and parents at several chunk lengths and prefix lengths (`scoring.rs:240–264`); the reviewed production loop caps chunks at 1024.

5. **The pruning guard targets only an unobserved actual last layer.** It requires no output range, no hidden-feature request, flat topology, the explicit fresh-scoring flag and the actual final layer index. It further requires owned full attention, no shared-KV source and no mixer convolution. The path retains pre-mixer normalization, complete QKVG projection, QKV normalization, RoPE and all K/V writes; the ordinary caller still accepts every row before the next part. Shared trailing layers disable this new pruning through actual-last-layer eligibility. A final requested row takes the ordinary path. Earlier-layer outputs remain necessary inputs to following layers.

   **The allowed downstream `mlp_conv` mixes tokens within the current chunk, but retains no sequence state.** `TransformerLayerConv` contains dimensions, immutable pre/post convolution objects, a linear coefficient projection and optional immutable transform/factors (`S/encodable_block/transformer_layer.rs:47–54`). Its pre/post encoders take only current input, coefficients and chunk length, allocate scratch and return outputs (`transformer_layer.rs:126–164`). `SeparableCausalConv` holds weights, optional bias and a kernel, with no history buffer; encoding writes a newly allocated scratch output (`S/encodable_block/convolution.rs:23–29, 73–99`). The Metal kernel reads `input[token - tokens_back]` with `tokens_back < min(kernel_size, token + 1)`, so history never crosses the current buffer boundary (`S/backends/metal/kernel/convolution/separable_causal_conv.metal:33–57`). The CPU implementation has the same bounds (`S/backends/cpu/kernel/convolution/separable_causal_conv.rs:30–54`). Thus the omitted MLP convolution cannot update future K/V or recurrent state: it runs after retained attention K/V preparation, and every output from this actual final layer is unobserved in the pruned part. This proves omission against the existing batched Uzu execution, not full-sequence equivalence for arbitrary convolution models. In a future final-batch partial-output optimization, its within-chunk mixing would require input halos and intermediate neighbor rows; the proposed tile candidate conservatively excludes it.

6. **The final state can be discarded without final acceptance.** The last requested logits are fully encoded before skipping acceptance (`scoring.rs:158–176`). No later batch consumes that state, and readout follows completion of all submissions. Reusing this state for continuation would require an explicit acceptance operation and a different ownership contract.

7. **Worker readout keeps the full-vocabulary normalization contract.** `candidate_readout` validates the vocabulary, finds its maximum and sums exponentials in the existing f64 iterator order before producing candidate log probabilities (`experiments/uzu-rust/src/scoring.rs:121–150`). Calibration then uses the candidate logits at the requested temperature. Candidate-only model projection or a parallel/GPU partition reduction would not automatically retain the returned log-probability bits, even when candidate calibration appears equivalent.

## Limitations worth correcting before reuse

| Priority | Source-backed limitation | Concrete follow-up |
| --- | --- | --- |
| P1, before broader integration | `deferred-state-init` changes creation/encoding for every GDN state in the built engine, not only states with the scoring-pruning flag (`delta_net.rs:459–519`). The flag records that fills were encoded, not that initialization completed. The CLI currently discards fresh state and fences native failures (`scoring.rs:285–297`). | Keep the feature scoped to this accepted scorer. Before exposing it through reusable library/generation state, add explicit initialization/submission ownership or a per-state scorer opt-in, and verify abandonment, encode failure and reuse. No current scorer failure is demonstrated. |
| P2, evidence gap | Native draining tests simulate returned completion errors; pruning tests exercise the eligibility predicate. They do not exercise real allocations, multi-buffer failure unwinding or every model exclusion (`scoring.rs:208–237`; `transformer.rs:390–408`). | Add focused backend failure-injection coverage when implementation work resumes: fail a later encoding after an earlier submit, fail multiple waits, and check destruction order and complete draining. Cover owned/full, ring, shared, mixer-convolution and hidden-feature paths without exposing request data. |
| P3, wording | The experiment report says “no layer convolution,” while the actual eligibility check excludes only `mixer_conv` (`transformer_layer.rs:350`). `mlp_conv` is downstream of retained K/V preparation and is omitted with the dead MLP (`transformer_layer.rs:431–445`). The state-free, chunk-local implementation is detailed above. | Describe the check as “no mixer convolution.” A downstream MLP convolution can be omitted when the actual final layer has no observed output because it retains no sequence state. If a stricter admission policy was intended, explicitly check both fields. |

## Prioritized exact-output optimization candidates

Every gain below is unmeasured. “Source-backed” means the redundant work exists in the reviewed source; it does not mean the proposed implementation has passed acceptance.

| Order | Candidate and evidence | Exactness conditions and expected scope |
| --- | --- | --- |
| 1 | **Reuse immutable CPU RoPE tables by configuration and absolute position.** `transformer.rs:275–282` invokes precalculation per chunk and request. `attention/rope.rs:29–35, 92–107` allocates two vectors, recomputes inverse frequencies and invokes sine/cosine before uploading constants. | Produce cached f32 values with the exact existing formulas and casts, key by complete immutable RoPE configuration, and retain absolute position indexing. Initially reuse CPU values while preserving constant allocation/upload and GPU kernels. This targets repeat setup work without prompt-state reuse. Measure CPU encoding time; no latency magnitude is known. |
| 2 | **Move immutable state-kernel setup out of each fresh request.** Every attention state constructs `KVCacheUpdateKernel` (`attention/state.rs:215`); every GDN state constructs `StateAdvanceKernel` (`delta_net.rs:470–484`). Flat attention accepts emit no copies and flat GDN accepts never invoke state advancement (`attention/state.rs:118–130`; `delta_net.rs:81–117`). | Store immutable kernels on model/mixer objects or introduce scoring-specific state that avoids unused tree/ring kernels. Preserve backend generality and ownership. Metal already caches pipelines (`S/backends/metal/context.rs:82–98`), so this removes constructor/cache/retain overhead rather than repeated compilation. Verify whether this remains measurable after existing deferred initialization. |
| 3 | **Construct flat topology and acceptance once, or provide a direct flat constructor.** The scorer allocates nodes and identity accept indices per part (`scoring.rs:156–157, 174`). `BatchTopology::new` additionally builds a stack and parent array (`batch_topology.rs:15–27`). | Reuse immutable bounded arrays for lengths through 1024 or derive parents directly as `[-1, 0, …]`; preserve every node, height, parent and full-accept bit. Do not route flat scoring through a tree kernel. This is a likely small CPU improvement. Avoid retaining prompt data in any topology cache. |
| 4 | **Retire completed batch pools during long requests.** The pending vector owns all batch pools until after all chunks are encoded (`scoring.rs:133–183`; `command_buffer.rs:287–303`). | Add a completion-polling/retirement facility that removes only terminal submissions, records any failure and still drains all outstanding work before state destruction. A bounded two- or three-batch pipeline is another experiment, but waiting may sacrifice overlap. Memory reduction is plausible; speed improvement is unestablished. Never recycle a pool solely because its host encoding ended. |
| 5 | **Reuse command argument-table setup after completion.** Command allocator/buffer reuse already exists (`command_buffer.rs:58–63`), but a new argument-table descriptor/table is constructed for each scoring batch (`command_buffer.rs:82–88`). | Extend the completed-command cache to reusable compatible table storage only after terminal completion. Verify Metal argument-table binding/update semantics and clear necessary state. This is lower priority without measured command-creation overhead. It must not permit mutable table sharing between in-flight buffers. |
| 6 | **Skip dead final-layer query preparation without changing K/V arithmetic.** The cache-only path discards a query buffer returned by `prepare_kv_and_queries` (`attention/mode.rs:62–71, 231–251`). `S/backends/metal/kernel/attention/attention_prepare.metal:49–71` calculates and writes independent query/key/value elements; the full QKVG projection and its query normalization still run. | Prototype an explicit query-write mask retaining original QKVG layout, K/V head offsets, element arithmetic and launch geometry. Merely passing `num_q_heads = 0` is incorrect for this projected layout: the helper then selects a tightly packed KV stride (`mode.rs:225–229`). Inspect generated specialization behavior and compare every vocabulary bit. Its limited removed work may not justify a new kernel. |
| 7 | **Prune complete dead output tiles in the final batch.** Current pruning helps only batches with no requested output. The final batch computes every row through final attention, output projection, normalization and MLP (`transformer_layer.rs:416–449`), then `transformer.rs:375–380` normalizes only the requested row. | This is the largest plausible remaining GPU opportunity in the reviewed narrow path. Retain full final-layer QKVG/KV preparation and the original logical suffix/batch size. Preserve the original attention family, split count, mask, GEMM engine, tile sizes and split-K reduction. Remove only complete unused row/query tiles, preserving all live-tile inputs and output indexing. Exclude sequence-mixing mixer/MLP convolutions, shared-KV and hidden-feature consumers until their dependencies are separately proved. This requires kernel work and full acceptance; no gain is established. |

Final-batch row pruning must not be implemented by changing batch size to one. Attention dispatch switches between grouped/GEMM, single-pass and two-pass paths based on suffix and KV lengths (`S/backends/metal/kernel/attention/mod.rs:116–156`). GEMM dispatch uses matrix shape (`S/backends/metal/kernel/matmul/mod.rs:264–282`), and split-K selection depends on the original output tile count (`S/backends/metal/kernel/matmul/gemm/selection.rs:90–118`). A smaller mathematically equivalent operation may change the floating-point reduction and fail the exact-output requirement.

Native identical-consecutive-input result reuse could avoid almost all repeat inference, but it changes this experiment's fresh-state policy (`experiments/uzu-rust/src/scoring.rs:240, 265`). It should remain a separate experiment with explicit full-token equality, invalidation and private-data lifetime rules. It cannot be folded into a claimed improvement of the present fresh/repeat benchmark.

## Recommended next experiment

After the current full-population comparison completes, profile CPU encoding, GPU prefill and final-layer work with aggregate diagnostics only. Implement one additive candidate at a time, starting with immutable RoPE/setup reuse if profiling supports it. Preserve the accepted binaries and receipts, use new output paths, and run whole-vocabulary bit equality plus candidate probabilities, calibration, typed decisions and boundary cases before timing. Include lengths around 1024 boundaries, changed/repeated/restored sequences, excluded model topologies and error-unwind ownership. Measure fresh and repeated requests separately and retain startup versus request timing. Current source findings justify experiments; they do not supply additional accepted speedups.
